## Decisions taken while building

- **Location.** The app lives in `kente/` because this repository also holds the Astra assessment site at its root.
- **Components.** The shadcn/ui registry was not reachable from the build environment, so `src/components/ui` holds hand-written components in the same style (cva + tailwind-merge), with no Radix dependency. Drawers use the native `<dialog>` element.
- **Auth and RLS.** Supabase Auth is used when `NEXT_PUBLIC_SUPABASE_*` is set. Otherwise a local email/password fallback (scrypt + HMAC-signed cookie) runs, for development and tests only. Every query runs inside `asUser()`, which sets `request.jwt.claims` and switches to the `authenticated` role, the same mechanism Supabase's `auth.uid()` reads, so one set of policies serves both.
- **Programme visibility.** Owners and leads see every programme in the workspace. Members, reviewers and viewers see only programmes they are a stakeholder on.
- **Assignee permissions.** Assignees who aren't owners or leads can change a task's status and add comments, but not other fields (enforced by a database trigger as well as the UI).
- **Metric progress.** The headline percentage is value progress, `(current − baseline) / (target − baseline)`, once a value has been recorded. Before that it's completed tasks over planned tasks.
- **Metric status** is derived (see `src/lib/domain/metrics.ts`):
  - Achieved at 100%.
  - Behind when the deadline has passed, or when at least half the open tasks are overdue.
  - At risk when any task is overdue, or when progress trails elapsed time by more than 25 points.
  - On track otherwise.
  It's computed on read for display and stored on writes for reports. Slice 4's nightly job should refresh the stored value.
- **Deleting an outcome** is blocked while tasks are linked to it.
- **Dashboard brief.** Until Kente Pulse (slice 8), the brief card is generated by rules from programme data only (`src/lib/domain/brief.ts`). Regenerate recomputes it.
- **Period preference** is stored in a cookie (`kente_period`). It moves to a user setting when a settings page exists.
- **Invites.** Invites without email configured show a copyable link. Someone already in the workspace is added to the programme straight away, without an invite. The invite must be accepted by the account whose email it was sent to.
- **"Project"** (PRD dashboard filter) has no table in the data model, so the dashboard filters by team and stakeholder. Revisit if projects become a level below programmes.

## Before going live

- Create the Supabase project, set `DATABASE_URL`, run `npm run db:migrate`, and set the Supabase env vars.
- Set `APP_URL`, `RESEND_API_KEY` and `EMAIL_FROM`.
- Set `APP_TIMEZONE` if the workspace isn't on West Africa Time (the default is `Africa/Lagos`).
